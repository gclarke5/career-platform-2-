# Exercise 05: Investigate a DNS or TLS failure

## 1. Setting and prediction

I initially predicted the DNS would be able to fix site.lab.example. I also
assumed the HTTPS connection must fail due to the server presenting a wrong
host name.

## 2. Failed check and evidence

I ran dig site.lab.example A +noall +answer that showed 198.51.100.24, showing
that DNS resolution worked. However, the HTTPS check with
curl -Iv https://site.lab.example/ failed with curl: (60) SSL certificate
problem: certificate subject name does not match target host name. The output
showed that the certificate subject was CN=old-vm.lab.example, while I was
connecting to site.lab.example.

Supplied output (simulated, from the exercise):

```text
$ dig site.lab.example A +noall +answer
site.lab.example.  300  IN  A  198.51.100.24

$ curl -Iv https://site.lab.example/
* Connected to site.lab.example (198.51.100.24) port 443
* Server certificate: subject: CN=old-vm.lab.example
* SSL: certificate subject name does not match target host name 'site.lab.example'
curl: (60) SSL certificate problem: certificate subject name does not match target host name
```

## 3. Diagnosis

It was an incorrect TSL hostname. the server presented a certificate for
old-vm.lab.example instead of site.lab.example.

## 4. Repair and repeated check

I would install the correct TSL certificate containing the site lab example so
it contains a valid host name.

Repeated check:

```text
dig site.lab.example A +noall +answer
curl -Iv https://site.lab.example/
```

Supplied follow-up output (simulated, from the exercise):

```text
$ dig site.lab.example A +noall +answer
site.lab.example.  300  IN  CNAME  current-app.up.railway.app.
current-app.up.railway.app.  300  IN  A  203.0.113.44

$ curl -Iv https://site.lab.example/
* Connected to site.lab.example (203.0.113.44) port 443
* Server certificate: subject: CN=site.lab.example
* SSL certificate verify ok.
< HTTP/2 200
```
