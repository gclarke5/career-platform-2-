# Exercise 06: Custom-domain email with Zoho Mail

**Domain:** `gavinclarke.me` (DNS hosted on Cloudflare)
**Mail provider:** Zoho Mail (US data center)
**Work done:** 2026-10-13 to 2026-10-15

## 1. Starting point

Before any changes I saved every DNS record in the zone with the Cloudflare CLI
(`cf dns records list --zone gavinclarke.me`) to
[dns-before-zoho.md](dns-before-zoho.md). At that point mail went through the
registrar's forwarding service: five MX records pointed at
`eforward1`–`eforward5.registrar-servers.com`, SPF only included the forwarder,
and there were no DKIM or DMARC records.

## 2. Mail records and their purposes

Final mail-related records in the zone (all DNS only, not proxied):

| Type | Name | Value | Purpose |
|---|---|---|---|
| MX | `@` | `mx.zoho.com`, priority 10 | Main server that receives mail for the domain. |
| MX | `@` | `mx2.zoho.com`, priority 20 | Backup, used if the first is unreachable. |
| MX | `@` | `mx3.zoho.com`, priority 50 | Last-resort backup. |
| TXT | `@` | `v=spf1 include:zohomail.com ~all` | SPF: lists which servers may send mail for the domain (Zoho's). |
| TXT | `zmail._domainkey` | `v=DKIM1; k=rsa; p=MIGf…IDAQAB` (1024-bit) | DKIM: public key receivers use to check Zoho's signature on outgoing mail. |
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:career-platform@gavinclarke.me` | DMARC: tells receivers to check SPF/DKIM alignment, take no action yet (`p=none`), and send reports. |
| TXT | `@` | `zoho-verification=zb34999741.zmverify.zoho.com` | Proves to Zoho that I control the domain. |

Changes I made along the way:

- **Removed the five `eforward*` MX records.** Three of them had priority 10,
  the same as `mx.zoho.com`, so senders would pick at random and some mail
  would still go to the old forwarder. Each MX record should have its own
  priority.
- **Removed the stale verification record** `zb01158665` once Zoho showed
  `zb34999741` as verified.

## 3. Lookup results

I compared what Cloudflare stores with what the public resolver `8.8.8.8`
returns. Final check on 2026-10-15:

```text
$ dig @8.8.8.8 MX gavinclarke.me
gavinclarke.me.   300  IN  MX  10 mx.zoho.com.
gavinclarke.me.   300  IN  MX  20 mx2.zoho.com.
gavinclarke.me.   300  IN  MX  50 mx3.zoho.com.

$ dig @8.8.8.8 TXT gavinclarke.me
gavinclarke.me.   300  IN  TXT  "v=spf1 include:zohomail.com ~all"
gavinclarke.me.   300  IN  TXT  "zoho-verification=zb34999741.zmverify.zoho.com"

$ dig @8.8.8.8 TXT zmail._domainkey.gavinclarke.me
zmail._domainkey.gavinclarke.me. 600 IN TXT "v=DKIM1; k=rsa; p=MIGf…IDAQAB"

$ dig @8.8.8.8 TXT _dmarc.gavinclarke.me
_dmarc.gavinclarke.me.  300  IN  TXT  "v=DMARC1; p=none; rua=mailto:career-platform@gavinclarke.me"
```

Cloudflare and `8.8.8.8` returned the same records.

Things I noticed:

- Right after deleting the old MX records, Cloudflare's own nameservers
  (`liz`, `sevki`) were already clean, but `8.8.8.8` still returned
  `eforward1` for a few minutes. It was a cached answer that expired with the
  300-second TTL.
- One check showed NXDOMAIN for the whole domain. That was my command, not
  DNS: in zsh, `dig @8.8.8.8 $q` with `q="MX gavinclarke.me"` doesn't split the
  variable, so dig looked up a name literally called `MX gavinclarke.me`.

## 6. Website and VM

While working on DNS I also confirmed the website no longer depends on the
Azure VM:

- `https://www.gavinclarke.me` returns `301` to `https://gavinclarke.me/`
  (Cloudflare redirect, keeps the path and query).
- `https://gavinclarke.me` returns `200` from Railway
  (`server: railway-hikari`).
- No DNS record points at the VM's IP.
- The VM `vm-career-platform` is deallocated. Its disk and static IP still
  exist and are still billed.
